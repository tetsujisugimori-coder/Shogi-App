## 1. P2-1：不要な候補選別処理の検証と改善

対象：
src/domain/shogi/quiescenceSearch.ts

問題：
現在は非捕獲成り候補を選別した後に、
stand-patによるalpha-beta枝刈りを判定している。

静的評価だけで探索を打ち切れる局面でも、
候補の駒価値、利き、取り返しの概算、
候補順位付けが先に実行される。

特に100msの時間制限では、この処理が
探索完了深さを悪化させる可能性がある。

### 修正方針

まず既存の処理順序と依存関係を調査する。

stand-patの判定を候補選別より前に移動できるか、
以下の条件で検討する。

- alpha-betaの評価結果を変えない
- PVと評価内訳を変えない
- cutoffCountを不正に変更しない
- skippedActionCountの意味を維持する
- 診断用のconsidered/addedと計測値の意味を維持する
- 王手中の全合法応手を維持する
- 中断例外と時間制限を維持する
- partial-root、fallback、完了反復を維持する
- 従来OFFと全候補ONの互換性を維持する

重要：
現行実装では、stand-patによる打切り時の
skippedActionCountが候補数に依存している。

したがって、候補選別を単純に省略すると
統計契約が変わる可能性がある。

この依存関係を無視した最適化は禁止する。

探索結果と統計を維持しながら安全に削減できる
処理があれば、最小限の修正を実施する。

両立できない場合は無理に処理順序を変更せず、
その理由と代替案を報告する。

単なる診断カウンターの帳尻合わせは禁止する。

### 追加テスト

- stand-patで即時打切りになる局面
- stand-patでは打ち切られない局面
- 非捕獲成り候補が0件の局面
- 非捕獲成り候補が複数ある局面
- 王手回避局面
- alpha-beta窓の境界
- 中断発生時
- 先手と後手の対称局面

修正前後の探索結果、PV、統計を比較する。

## 2. P2-2：選別オプションの検証・複製の整合性

対象：
src/domain/shogi/quietPromotionSelection.ts
src/domain/shogi/twoPlyAlphaBetaAi.ts

問題：
validateQuietPromotionSelectionでは、
maxCandidatesの値を検証している。

しかし、検証済みオブジェクトを
スプレッド構文で複製する実装では、
継承プロパティや列挙不可プロパティが
複製されない可能性がある。

その結果、検証に成功した設定が
探索開始時の再検証で失敗することがある。

### 修正方針

検証と正規化の契約を統一する。

- maxCandidatesは正の安全な整数のみ許可する
- 0、負数、小数、NaN、Infinityを拒否する
- 未知の設定項目を拒否する
- null、配列などの不正入力を拒否する
- 継承プロパティの扱いを明確化する
- 列挙不可プロパティの扱いを明確化する

検証済み設定は、必要な値を明示的に取り出し、
新しい設定オブジェクトを構築する方式を優先する。

ただし、継承値を拒否する設計も選択可能とする。
どちらの場合も、公開APIの振る舞いを明確にし、
検証成功後に複製が原因で失敗しないことを保証する。

### 追加テスト

- 通常の設定オブジェクト
- Object.createによる継承値
- Object.definePropertyによる列挙不可値
- 明示的なundefined
- 不正な数値
- 余分なプロパティ
- OFF/全候補ON/選択方式の相互排他
- TT identityへの反映

既存の正常な呼出しが壊れないことを確認する。

## 4. 性能確認

P2-1で探索処理を変更した場合は、
既存のA/B/C比較条件を可能な限り再利用する。

A：従来OFF
B：全候補ON
C：選択方式 maxCandidates=1

最低限、以下を比較する。

- 固定深さd1/d4の実時間
- q探索ノード数
- 100msの完了深さ
- 1000msの完了深さ
- deadline超過
- 選別処理の費用
- 探索結果とPV

修正前後を同一条件で比較する。
