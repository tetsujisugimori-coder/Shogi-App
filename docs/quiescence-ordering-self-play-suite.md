# 複数開始局面・先後交代セルフプレイスイート基盤

## 目的と範囲

`original` と `material` の静止探索順を、同一の平手初期局面だけに閉じず、固定された複数の合法開始局面で安全かつ再現可能に実行する研究用基盤です。各局面では既存の先後交代A/B対局ペアを1組だけ同期・直列で実行します。A/Bの差は既存どおり静止探索順だけであり、評価プリセット、通常探索順、静止探索深さ、最大通常探索深さ、100ms設定、最大plyは `SELF_PLAY_CONFIG` を再利用します。

本資料は実測結果を含みません。この変更では長時間の実探索を実行していません。

## 開始局面カタログ

すべて `createInitialBoardState()` から、`getLegalActions()` で意味的に一意な手を探し、`executeLegalAction()` で順に適用して生成します。盤面配列の直接変更や、履歴を持たない人工局面は使用しません。各 `create()` は独立した新しい `BoardState` を返し、3局面とも4手または0手の偶数手後、先手番です。

| ID | 開始局面 | 固定手順 | 目的 |
| --- | --- | --- | --- |
| `standard-hirate` | 平手初期局面 | なし | 既存パイロットとの連続性を保つ基準 |
| `rook-pawn-opening-76-34-26-84` | ▲7六歩 △3四歩 ▲2六歩 △8四歩後 | ▲7六歩 △3四歩 ▲2六歩 △8四歩 | 角道と飛車先の異なる分岐 |
| `rook-pawn-exchange-26-84-25-85` | ▲2六歩 △8四歩 ▲2五歩 △8五歩後 | ▲2六歩 △8四歩 ▲2五歩 △8五歩 | 双方の飛車先を一段進めた分岐 |

手が見つからない、複数候補になる、または適用できない場合は、局面IDと1始まりの手順番号を含むエラーにします。

## 実行・集計・署名

`runSelfPlaySuite` はカタログ順に1局面ずつ処理し、各局面で既存 `runPairedSelfPlayMatch` を1回呼びます。そのため、各局面の2局はA先手/B後手、続いてB先手/A後手です。`failed` と `max_plies` は既存の観測outcomeとして保持し、後続局面も実行します。

局面別結果には `scenarioId`、表示名、provenance、`createPositionKey` による `initialPositionKey`、実行順、完全な既存ペア結果、局面別summaryを保持します。スイートsummaryは `aWins`、`bWins`、`draws`、`maxPlies`、`failures` をbigintで合算し、総数が「実行済み局面数 × 2局」と一致することを検証します。runner例外または集計不変条件違反は `scenarioId` を付けて例外にし、完全な測定のようなsummaryは返しません。

既存の指し手列だけの署名は維持します。追加した複合署名は `SHA-256(JSON([createPositionKey(initialState), gameSignature(actions)]))` で、実際の開始局面キーと意味的な指し手列の両方を反映します。局面別・全体でユニーク数、重複局数、署名ごとの対象局を集計します。したがって、異なる開始局面で同じ形の指し手列になっても別署名であり、同じ開始局面と同じ指し手列だけが重複です。

`null` の探索観測値は既存集計どおり欠測のままで、0へ置換しません。bigintは十進文字列、非有限数は既存CLIと同じ文字列表現でJSON化します。

## CLI

`npm run measure:quiescence-ordering-self-play-suite` は引数なしの固定設定です。`RUN` に開始日時、Node/npm/OS/CPU、HEAD、dirty、実行方式、コマンド、主要ソースのSHA-256を出します。その後に `SUITE_CONFIG`、実行前の `SCENARIO_START`、局面別 `RECORD`/`GAME`/`SCENARIO_SUMMARY`、全完走時だけ `SUITE_SUMMARY`、最後に `END` をJSON行で出します。例外では `ERROR` に `scenarioId` とメッセージを出し非0で終了します。

100msは厳密な実行上限ではありません。既存の時間制限探索は、合法手フォールバックである深さ1を期限から除外する契約を持ちます。

## 解釈の境界と次段階

同一開始局面の繰り返しだけを独立標本とは扱えません。複数開始局面を導入しても、この基盤だけで棋力差、勝率、Elo、統計的有意差、最適順序を直ちに証明しません。`material` を既定化せず、通常対局設定・Worker/UI・探索本体・評価係数・SEE・乱数定跡・並列対局も変更しません。

次段階は、この固定カタログの少数局面を使ったパイロット測定です。測定を実施するときも、出力を捏造せず、実行条件と欠測・失敗をそのまま記録します。
