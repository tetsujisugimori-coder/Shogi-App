# 静止探索順 original / material: 複数ペア実対局パイロット

## 目的と実行条件

PR #132の`runRepeatedPairedSelfPlayMatches`へ既存の`analyzeTimeLimitedIterativeDeepeningAlphaBetaSearch`を接続し、勝敗件数と探索観測値を保存する測定基盤。棋力の優劣を決定する実験ではない。

```sh
npm run measure:quiescence-ordering-self-play
```

| 条件 | 値 |
| --- | --- |
| 開始局面 | 標準平手初期局面（全局共通） |
| 参加者 | A=original、B=material（静止探索順のみ異なる） |
| 評価プリセット / 通常探索順 | standard / standard |
| 静止探索の追加深さ | 1 ply |
| 最大通常探索深さ / 各手時間制限 | 4 / 100ms |
| 研究上限 | 各局120ply |
| 実行 | 3ペア6局、各ペアA先手/B後手→B先手/A後手、同期・直列 |
| ウォームアップ / 乱数による局面選択 | なし / なし |

設定は`SELF_PLAY_CONFIG`一か所に定義し、CLI開始時にも出力する。深さ1は合法手フォールバックとして時間制限から除外されるため、100msは厳密な実行上限ではない。探索本体は改造しない。

## 観測値・保存形式

[生出力](quiescence-ordering-self-play-output.txt)の`RUN`に日時、Node/npm/OS/CPU、HEAD、dirty状態、主要ソースSHA-256、`CONFIG`に条件、`RECORD`に各plyの既存観測、`GAME`に各局の詳細と指し手列、`SUMMARY`に全体/先後別集計、`END`に終了日時と終了コードを保存する。

着手数は実際に適用できたply数。失敗した探索/着手の未取得観測は合計に含めない。時間は探索APIが返した時間（未完了反復を含む）で、対局の複製/合法性検証/表示を除く。`deepest`と`completedTotals`はそれぞれ最深完了反復/全完了反復の統計を着手間で足し、通常探索と静止探索は別カウンタである。中断した未完了反復の統計はない。

欠測を含む項目の合計は`null`とし、`unavailable`で欠測数を示す。未定義/不正な観測値を0に補完せず、既存対局境界の失敗または集計エラーにする。整数統計と全体outcomeのbigintは十進文字列、非有限数はInfinity/-Infinity/NaNの文字列で保存する。

シグネチャは指し手の意味的フィールドを固定順配列にしたSHA-256。時間・勝敗を含めない。drop駒IDを保持する。同じ初期局面からの指し手列を識別し、失敗時の空/部分棋譜もその列で数えるのでoutcome/ply数と合わせて読む。

## 解釈と次段階

3ペア6局はパイロット測定である。同じ開始局面から同一棋譜が繰り返される場合、それらを独立した6標本と見なしてはいけない。棋譜が異なっても、単一開始局面の小規模測定が独立性や代表性を保証するものではない。時間制限探索の完了深さと選択手はOS負荷・JIT・GCにも依存する。

**複数開始局面や定跡分岐を導入するまでは棋力差を判断できない。** 勝敗件数と観測値だけを報告し、勝率、Elo差、統計的有意差、最適順序、material既定化やoriginal廃止を導かない。

次段階は複数開始局面または定跡分岐を使った対局スイート。局面ごとの先後交代、条件/ソースの識別、指し手列の重複検査を引き継ぎ、異なる局面での観測を増やす。

UI/Worker測定画面、通常対局設定、探索/静止探索本体、評価係数、SEE、交換形式、乱数導入、並列対局、定跡生成、外部依存、優劣の自動判定は今回の対象外。
