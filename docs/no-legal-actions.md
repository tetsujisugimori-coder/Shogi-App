## 規則と採用仕様

- [日本将棋連盟・対局規則](https://www.shogi.or.jp/match/taikyoku_rules/): 第2条4・5項は玉を詰ますことを目的とし、詰みを玉の捕獲を防げない状態として定義。第6条は詰み・投了・入玉・反則による終了を規定。第10条は王手放置、自玉を敵の利きへ動かす行為、時間切れ等を規定している。合法手がないという**局面そのもの**を即反則負けにする条項は、確認した公開規則には見つからなかった。
- [日本将棋連盟・王手と詰み](https://www.shogi.or.jp/knowledge/shogi/04.php): 詰みを防げない王手として説明している。王手でない局面を通常の詰みと同一視する根拠にはしない。
- [FESA Laws of Shogi, 2024-09-23改定](https://fesashogi.eu/wp-content/uploads/2025/05/FESA-Rules-ver-2024-09-23.pdf): Article 1.2は王への捕獲の脅威と合法応手なしをcheckmateの条件とする。Article 5も確認したが、非王手の合法手なしを直接定める条項は確認できなかった。FESA規則を日本将棋連盟の規則として扱っていない。

交互に合法着手を行う一般規定から「指せなければ負け」と解釈する余地はあるが、自動終局の直接規定と区別する。チェスのステイルメイトによる引き分けを流用しない。既存READMEにも自動勝敗の選択がなかったため、再現結果と選択肢を提示した。ユーザーが2026-10-14に **「手番側の負け（専用理由『合法手なし』）」** を選択したことをアプリ仕様の根拠とする。公式規則の確定事項とは主張しない。

両玉がある局面で、盤上移動と持ち駒の合法な駒打ちを合わせた応手がない場合:

- 王手あり: 従来どおり `checkmate`。`isCheckmate` の王手条件は変更しない。
- 王手なし: `status: 'ended'`, `endReason: 'no_legal_actions'`、次の手番側が敗者、着手側が勝者。
- 表示例: `終局 / 後手勝ち（先手の合法手なし）`。反則や投了として記録しない。
- 優先順位: 詰み／合法手なし → 連続王手の千日手 → 通常の千日手 → 500手規定。着手後の決着を既存の詰みと同じ位置で優先する。千日手との同時成立テストの履歴は人工的なもので、実対局で同時発生した事例ではない。
- 入玉宣言・合意持将棋・投了は既存の独立した操作のまま。終局後の着手拒否と入力state非破壊を維持する。

## 再現局面と変更前後

`src/test/no-legal-actions.cases.ts` と `scripts/reproduce-no-legal-actions.ts` で再現できる。
先手が動けなくなる直前の盤上配置:

| 駒 | 座標 | row,col |
|---|---|---|
| 先手玉 | 9九 | 8,0 |
| 後手玉 | 1一 | 0,8 |
| 後手飛車 | 8七 | 6,1 |
| 後手金 | 9六 | 5,0 |

残り36枚はすべて後手の持ち駒。先手持ち駒なし。平手の40枚から駒を取り出して配置し、各IDは一意、両玉各1枚、9×9盤面を保つ。後手金 `9六→9七` は公開 `executeMove` で合法に適用できる。金が `9八`、飛車が `8八・8九` を制御し、先手玉の現在地 `9九` は王手にならない。先手の盤上移動数・駒打ち数・全合法手数はいずれも0。

後手側のケースは盤を180度回転し、全駒の所有者と手番を交換する。先手金 `1四→1三` の後、後手玉 `1一` が動けない。残り駒は先手持ち駒。

いずれも**構成局面**であり、平手からの到達可能性は証明していない。通常対局での発生例ではない。直前の構成局面からの1合法着手と、その後の自動終局まで検証した。

| 経路 | 基準main | 修正後 |
|---|---|---|
| 王手／通常の詰み照会 | false / false | false / false |
| 合法着手後の状態 | active / result:null | ended / no_legal_actions、着手側勝ち |
| 非終局の照会用コピーへのαβ探索 | 手:null、評価:null、内訳は有限・非終局 | 手:null、評価:-Infinity、内訳loss |
| 同コピー、時間制限0ms | 手:null、timedOut:true、fallback | 手:null、timedOut:false、no-legal-actions |
| Worker | 成功応答の中に手なしfallback | 成功応答の中にno-legal-actions、loss |
| 単独WorkerのUI受信 | 手なしを探索エラー表示 | 自身の合法手照会で確認して終局表示 |

探索の非終局rootで合法手0を確認した後だけ終局内訳を作る。全評価葉に新しい合法手生成を追加しない。通常の評価APIはadjudication済みstateのstatus/resultを評価する従来仕様を保つ。深さ0の静的評価も従来仕様を維持する。玉欠落の既存人工局面には新たな勝者を作らない。時間制限探索で終局済み入力を正の予算で読む既存の完了反復形式は維持し、0msの終局済み入力は手なしを時間切れと区別する。

キャンセルは従来のAbortError、探索例外はWorker failureとして維持。合法手がある0ms入力は従来どおり合法なfallbackとtimedOut:true。確認された手なしに架空の着手・fallbackを作らない。自対局実行器も手なしを自身で確認して決着とし、架空のplyを履歴に追加しない。

## 保存・読込・再生

JSON version 1の結果unionへ `no_legal_actions` を追加し、保存・構文検証・ドメイン型への復元を更新する。既存理由・既存棋譜の読み込みは維持。新理由を知らない旧版の読込器による新棋譜の読み込みは保証しない。

既存読込器は平手から合法手を再実行し、局面・結果・スナップショットを照合する。今回の構成局面は従来どおり `inconsistent_record` で拒否する。保存JSONに新理由が保持され、結果の型検証を通ったうえで既存の再実行整合検査により拒否されることを検証した。任意局面の読込対応を追加していない。新理由を含む**平手からの完全な棋譜**の保存→読込成功は、到達手順がないため実行検証できていない。

KIFではこの理由に対応する交換用終局語を確定していない。詰み・投了・反則等へ置換せず、JSON保存を案内する明示エラーを返す。既存KIF終局理由は維持する。

履歴indexによる既存復元APIで終局直前へ戻るとactive/result:null、最後のindexでは終局結果を保持する。UIの履歴再生と検討分岐はこの既存スナップショット復元に従う。終局前への復元テストをUndoに相当するドメイン確認として実施した。専用Undo UIや任意局面の読込を追加していない。
