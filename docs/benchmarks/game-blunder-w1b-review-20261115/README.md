## Reporter contract and aggregation

The installed Vitest **4.1.11** implementation and declarations were inspected directly (`reporter-implementation-excerpt.txt`, `suite-definition-excerpt.txt`; full installed implementation hashes are in execution dependency manifests). `getSuites(files)` counts each file AND every nested describe, including empty describes. JSON `testResults` has one element per file. It does not expose the complete suite tree or its states, so equality with `testResults.length` is not the contract. The runner's reporter records every runtime suite ID/file/root/mode/state. Aggregates are checked against those states with the exact reporter rules: failed = state fail; pending = run/queued or mode todo; passed = total minus failed and pending. Per-file state, assertion totals/statuses, inventory occurrences, completion, success and exit code are also checked. Actual recorded failures remain FAIL with contradiction details.

This JSON reporter emits **neither `unhandledErrors` nor `numRuntimeErrorTestSuites`**; their absence does not prove a clean run. Optional synthetic extensions are checked for type, nonzero/nonempty errors, impossible totals and contradictory presence/counts. The runtime reporter additionally records `onTestRunEnd` errors and completion reason; logs and process exit are retained. `reporter-submission/outcomes.json` is real Vitest output: an unhandled-exception fixture produces JSON success=true with process exit=1 and one runtime error, and is INVALID.
