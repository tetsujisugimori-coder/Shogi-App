# 盤上手の王手判定用盤面複製

## 対象と原因

PR #168 後の `main` `103ad15af2bb734da7f332f91add7dc190a8e745` を基準にした。作業開始時はクリーンで、GitHub API の main SHA と一致した。通常の `git fetch` は Windows の `SEC_E_NO_CREDENTIALS` で失敗した。保存棋譜 SHA256 は `8b269f95bb3be422ab87fe2e64d1a5dcc342cf53048eb63d3c2424ebfbf1e552`。

`getLegalActions` と静止探索の診断経路はどちらも `getLegalMoves` を使う。盤上の疑似手ごとに `simulateMoveSquares` が81マスの `BoardSquare` と駒を複製し、元位置を空にして移動先に駒を置く。その後の `isKingInCheck` と攻撃判定は盤面を読むだけである。複製は候補1件につき81マス、着手反映は2マスで、他の処理はこの関数内にない。変更前の診断ON・固定深さ1では4局面で計23,447回呼ばれた。以前のPRで最適化した持駒打ちの盤面準備とは別の呼出箇所である。

王手判定専用の非公開関数で外側配列、移動元と移動先の行、2マスのオブジェクトだけを複製し、既存の疑似手順と王手判定を維持した。変更されないマスと駒は判定中だけ共有される。判定関数は読み取り専用で、結果の盤面は外部に返さない。元盤面と持駒を一時変更しないため、例外や早期returnでも復元処理を必要としない。公開 `simulateMoveSquares` の深い複製は維持した。探索、評価、手順序、時間制限、Worker/UIは変更していない。

## 条件と結果

同一の Windows 10.0.26200 x64、Intel Core i7-14650HX、Node v24.20.0、npm 11.17.0。4局面、標準評価・標準順序、静止追加1手、100ms・最大深さ4。保護された入力を使用し、各局面で2回ウォームアップ後に5回測定した。100ms探索は診断OFF/ONを交互に、固定深さ1の補助計測は診断ONで直列に完走させた。変更前→変更後の順で実行した。JSONLの `dirty=true` は計測器が出力ファイルを作ってから status を記録するためで、変更前のコードは main のままである。
