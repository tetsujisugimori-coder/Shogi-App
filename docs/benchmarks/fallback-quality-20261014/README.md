## 具体的な手順確認

tactics.jsonlでは全root合法手を実行し、終局理由checkmate・勝者・`isCheckmate`の一致で即詰みを検査した。先頭手後と参照手後には相手の全合法応手を実行し、同じ判定で1手詰みを検査した。全10局面で即詰み手・先頭手後の被1手詰みは未検出。先頭手以外の全候補について相手応手を全列挙したわけではなく、深い詰みは調べていない。

駒得損の例はg4-p89。先頭手は先手のと金 `(row=0,col=3)→(0,2)`。相手の合法手で玉 `(0,1)→(0,2)` がと金を取る。この2手を公開APIで実行すると先手側material差が5,400→4,800、600低下する（盤上のと金500＋相手持ち駒の歩100）。参照手の飛車打ち `(4,7)` では、53合法応手をすべて実行した後の最悪materialが5,400で、元局面からの低下をこの1応手範囲で回避する。先頭手後の応手は3手すべて確認した。

g1-p93にも、先頭の歩成り後に相手飛車が `(4,3)→(7,3), promote` で先手飛車を取り、元局面からmaterialが1,800低下する手順があった。参照の飛車 `(7,3)→(4,3)` 後は113合法応手の最悪materialでも元局面より2,000高かった。各手・合法応手数・最悪応手・material・root/childからの差を保存した。

これは**合法手を実行して確認した1応手の駒得損**。その後の取り返しや長期の補償を証明していないため、「ただ取り」「真の棋力低下」は断定しない。単なる評価差から駒損を推定したものではない。materialは通常の公開DEFAULT_MATERIAL_VALUE_TABLEで、standard評価全体の数値とは別に扱う。
